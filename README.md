# Kex Programming Language (`.kx`)

Kex is a lightweight, interpreted programming language written in Rust. It ships as a
single `kex.exe` binary, a Windows installer, and an official VS Code extension with
syntax highlighting out of the box.

- **Engine** — `kex/`, the Rust CLI (`KEXDRUN`). Tokenizer, parser, tree-walking
  interpreter and **176 builtins**. No external crate dependencies, no runtime requirements.
- **kexco** — `kexco/`, the standard library pack. A web platform with DOM, events, timers,
  storage, fetch, **and a real localhost HTTP backend**, bridged to a Node.js host. Its
  headless adapter runs the same `.kx` code in a terminal with no browser.
- **Starter site** — `examples/webapp/`, generated by `kex new web <dir>`.
- **VS Code extension** — `vscode-extension/`, grammar and language configuration.
- **Installer** — `installer.iss`, an Inno Setup 6 script that packages `kex.exe`, `kexco/`
  and the `.vsix`, adds the install directory to `PATH`, and installs the extension.

## Quick start

### Windows installer

Download `KexSetup.exe` from the releases page, or compile it yourself (see
[Building](#building)). Run it, leave **Add Kex to System PATH** checked, then open a
new terminal.

### Build from source

```bash
git clone https://github.com/click-for-games/Kex.git
cd Kex
cargo build --release --manifest-path kex/Cargo.toml
kex/target/release/kex.exe kex/main.kx
```

The interpreter itself has no runtime dependencies. Node.js is only needed for `kexco`,
the web library and the localhost server.

### Create and run a website

```bash
kex new web my-site
kex serve my-site/main.kx --port 8080
```

Open `http://127.0.0.1:8080`. The starter site serves `my-site/public/` and exposes
`GET /api/hello` and `POST /api/echo`.

## Building

### 1. The engine

```bash
cargo build --release --manifest-path kex/Cargo.toml
# -> kex/target/release/kex.exe
```

### 2. The VS Code extension

```bash
cd vscode-extension
npx @vscode/vsce package --out kex-lang-1.0.0.vsix
```

`installer.iss` expects the archive at `vscode-extension/kex-lang-1.0.0.vsix`, so keep that
exact name and location.

### 3. The installer

Requires [Inno Setup 6](https://jrsoftware.org/isinfo.php). Run the script from the
**repository root**, because its `[Files]` entries are relative to the working directory:

```bash
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer.iss
# -> Output/KexSetup.exe
```

The installer installs to `{autopf}\KexEngine`, creates a `Kex Language` start menu group,
and then:

1. appends `{app}` to the **system** `PATH` (so `kex` works in any terminal), and
2. runs `code --install-extension "{app}\kex-lang-1.0.0.vsix" --force` if the VS Code CLI
   is present.

Both steps are skipped silently if the tools are unavailable.

## CLI

```
kex <file.kx>              run a script
kex run <file.kx>          run a script
kex check <file.kx>        parse a script without running it
kex serve <file.kx>        run a web backend
kex new web <dir>          scaffold a starter website
kex builtins               list the standard library
kex pack <subcommand>      manage kex libraries
kex version                print the version
```

`kex serve` options:

| Option | Meaning |
| --- | --- |
| `--port N`, `-p N` | Port to pass as `KEX_PORT` (default `8080`) |
| `--host ADDR`, `-H ADDR` | Bind address to pass as `KEX_HOST` (default `127.0.0.1`) |
| `--root DIR` | Static file root to pass as `KEXCO_ROOT` (default: script directory) |

`kex pack` (aliases `kex kx`, `kex pkg`):

| Subcommand | Description |
| --- | --- |
| `install <name\|path\|url>` | Install a package, an archive, or a local folder. Aliases: `i`, `add` |
| `list` | List installed packages. Alias: `ls` |
| `info <name>` | Show package metadata. Alias: `show` |
| `remove <name>` | Uninstall a package. Aliases: `uninstall`, `rm` |
| `update [name]` | Reinstall a package, or list the registry when no name is given |
| `search [text]` | Search the registry |
| `path` | Print the pack directory |
| `home` | Print the Kex home directory |
| `host` | Report whether a host bridge is attached |

**Exit codes:** `0` success, `1` lexer/parser/runtime/pack error, `2` CLI usage error.

## Language tour

### Comments and declarations

```kex
// line comment
/* block
   comment */

let mutable = 1;      // let is reassignable
const FIXED = 2;      // const is immutable
```

Note the inversion relative to JavaScript: **`let` is mutable, `const` is immutable.**
Semicolons are optional everywhere.

### Strings and interpolation

Double quotes interpolate, single quotes are literal, and backticks make multiline
templates:

```kex
let n = 10;
kxout("sum is {n + 2}");       // sum is 12
kxout('no {interpolation}');   // no {interpolation}

let html = `
  <h1>{title}</h1>
  <p>{body}</p>
`;
```

Interpolation accepts format specs:

```kex
let n = 10;
kxout("{n:x} {n:04} {n:.2f}"); // a 0010 10.00
kxout(format('{:x} {:04}', n)); // a 0010
```

Use a single-quoted template with `format()` so the braces are not parsed as interpolation.

Escapes: `\n \t \r \0 \\ \' \" \{ \}`.

### Control flow

```kex
if (n % 2 == 0) {
    kxout("even");
} elif (n % 3 == 0) {   // `else if` also works
    kxout("three");
} else {
    kxout("odd");
}

let total = 0;
for i in range(1, 5) { total = total + i; }
for (let j = 0; j < 3; j++) { total += j; }   // classic for

let k = 0;
while (k < 3) { kxout(k); k++; }
do { kxout("once"); } while (false);

switch (n) {
    case 10: kxout("ten"); break;
    default: kxout("other");
}
```

Switch cases fall through unless you use `break`; `break` now stops the switch instead of
escaping it as an error.

### Errors

```kex
try {
    error("boom");
} catch (e) {
    kxout("caught " + e);
} finally {
    kxout("done");
}
```

### Functions

```kex
fn add(x, y) { return x + y; }

let square = (v) => v * v;
let addAll = (a, b) => { return a + b; };
```

Arrow functions are anonymous function expressions and capture their enclosing scope.

### Arrays and objects

```kex
let nums = [5, 3, 9, 1];
nums[0] = 42;                  // index assignment mutates in place
nums = nums.sort();            // mutating methods write back through assignment

let cfg = { host: "local", port: 8080 };
let copy = { cfg, debug: true }; // object shorthand
kxout(cfg.host, keys(cfg));
```

### Operators

`+ - * / % **` · `== != < > <= >=` · `&& || !` · `& | ^` · `<< >>` · `??` (coalesce) ·
`?:` (ternary) · `..` `..=` `.. by` (ranges) · `++ --` ·
`= += -= *= /= %= &&= ||= ??=`

Numbers are `f64` and support `0x` / `0b` / `0o` radix literals, `1_000_000` digit
separators and `1e-3` exponents.

### System calls

```kex
kxsys "echo hello";   // or: syscall "echo hello"
```

Runs through `cmd /C` on Windows and `sh -c` elsewhere.

### Modules

```kex
import "kexco";

kxout(kexco_version);
```

A module runs once and its top-level declarations are copied into the importing scope;
`export` marks a name explicitly. Local `kexco/` folders are found before installed packs.

### Method syntax

Builtins are also reachable as methods on strings, arrays and objects. Many have a
`camelCase` alias, which is the *only* place `camelCase` is accepted:

```kex
let s = "  AbC  ";
kxout(s.trim(), s.upper(), s.contains("b"), s.repeat(2));
kxout(s.startsWith("A"), s.indexOf("b"), s.charAt(0), s.padStart(3, "0"));

let a = [3, 1, 2];
kxout(a.len(), a.sort(), a.slice(0, 2), a.join("-"), a.sum());

let o = { a: 1, b: 2 };
kxout(o.keys(), o.values(), o.hasKey("a"), o.is_empty(), o.entries());
```

`len` is now a valid method name, so `a.len()` works alongside `length(a)`.

Array values are copied, but **mutating method calls write their result back to the
receiver variable** when the receiver is a simple name:

```kex
let a = [];
a.push("x");       // a is now ["x"]
a = push(a, "y");  // function form still needs assignment
```

Index assignment (`nums[0] = 42`) mutates in place.

## kexco — the standard library pack

`kexco` gives Kex a web platform. It requires **Node.js on `PATH`**, which the engine
spawns as a child process and talks to over stdio.

```bash
kex pack install kexco
```

```kex
import "kexco";

fn render(items) {
    let list = query("#list");
    for item in items {
        append(list, element("li", item.label, "entry"));
    }
}

route("GET", "/api/items", 200, '{"ok":true}');
kxout("requests -> ", len(routes()));
```

It provides DOM (create/query/append/attributes/classes/styles/data/HTML), events, timers,
local and session storage, fetch against a routable fake backend, JSON, base64 and URL
helpers, plus the localhost server API below.

### Events and timers are pumped

Handlers are registered by integer id and stored on the Kex side. The host records what
happened into a queue; `pump()` drains it and dispatches. Nothing is ever invoked across
the bridge. Timers are deterministic: the clock only moves when you call `tick(ms)`.

### The headless adapter

`kexco/lib/kexco.js` ships a complete in-memory web platform — a real element tree with
working `querySelector`, two independent storage objects, an event queue and a route
table. It is selected automatically when no browser `document` is present, so tests and
scripts run identically in a terminal:

```
kexco 1.1.0 host ready (headless adapter, http backend, win32)
```

## Localhost backend

The real HTTP listener lives in the Node host. Requests are queued; Kex code dispatches
them through `server_pump()` and answers with a returned response object (or an explicit
`server_respond()`). This keeps all application code inside Kex.

```kex
import "kexco";

server_static("public", "/");

server_route("GET", "/api/items/:id", (req) => {
    return json_response({ "id": req.params.id, "ok": true });
});

server_route("POST", "/api/echo", (req) => {
    return { "status": 201, "body": req.body, "headers": { "Content-Type": "text/plain" } };
});

let bound = server_listen(8080, "127.0.0.1");
kxout("listening on " + bound.address);
server_run(50);
```

| Function | Purpose |
| --- | --- |
| `server_listen(port, host)` | Start the listener; returns `{ host, port, address }` |
| `server_close()` | Stop the listener |
| `server_running()` / `server_address()` | Inspect the listener |
| `server_route(method, path, handler)` | Register `GET /users/:id`-style routes |
| `server_unroute(method, path)` | Remove a route |
| `server_routes()` | List registered routes |
| `server_static(dir, prefix)` | Serve files from `KEXCO_ROOT/dir` |
| `server_wait(ms)` | Wait for a queued request (or timeout) |
| `server_pump()` | Run all queued Kex handlers and send responses |
| `server_run(ms)` | Cooperative `wait` + `pump` loop until closed |
| `server_respond(id, status, body, headers)` | Answer a request manually |
| `server_simulate(method, path, body, headers)` | Inject a request without a socket, for tests |
| `server_requests()` / `server_last_response()` / `server_pending()` | Inspect the queue and log |
| `json_response(body, status)` / `html_response(body, status)` | Response helpers |

The request object passed to a handler contains `id`, `method`, `path`, `url`, `query`,
`params`, `headers` and `body`. A handler may return `null` if it calls `server_respond()`
itself. If no route matches, `server_static()` is tried before a JSON `404`.

Path traversal is rejected for static files. Missing paths ending in `/` fall back to
`index.html`.

### Host bridge protocol

One JSON object per line, over stdin/stdout (stderr is free for logging). Values use a
tagged codec (`z` null, `b` bool, `n` num, `s` str, `a` array, `o` object, `r` range,
`e` error, `f` function). See [docs/PROTOCOL.md](docs/PROTOCOL.md).

```jsonc
// request
{"id":1,"fn":"dom.query","args":[{"k":"s","v":"#app"}]}
// response
{"id":1,"ok":true,"value":{"k":"o","v":{}}}
// failure
{"id":1,"ok":false,"error":"selector not found"}
```

The engine looks for `kexco.host.js` next to the script, in local ancestor `kexco/`
folders, in the installed pack, and next to the executable.

## Packages

The pack directory resolves in this order:

1. `$KEX_HOME/pack`
2. `%LOCALAPPDATA%\kex\pack` (Windows)
3. `~/.kex/pack`

`kex/registry.json` is compiled into the binary, so `kex pack install kexco` works with no
setup. On-disk `registry.json` files take precedence, and a package can also be installed
straight from a folder or a `.zip`/`.tar.gz` URL:

```bash
kex pack install ./kexco
```

### Environment variables

| Variable | Purpose |
| --- | --- |
| `KEX_HOME` | Overrides the Kex home / pack directory |
| `KEX_PORT` | Default port used by scaffolded server apps |
| `KEX_HOST` | Default bind address used by scaffolded server apps |
| `KEXCO_ROOT` | Project root for static files and host discovery |
| `KEXCO_HOST` | Absolute path to the host bridge script |
| `KEX_NO_HOST` | Set to disable the host bridge entirely |
| `KEXCO_ADAPTER` | `browser`, `headless` or `auto` (default) |
| `KEXCO_ROUTES` | JSON seed for the headless route table |
| `KEXCO_STORAGE` | JSON seed for headless `localStorage` |
| `KEXCO_DOC` | JSON seed for the headless document tree |

## Known limitations

- `kxsys capture "cmd";` parses as a statement, but `let out = kxsys capture "cmd";` is a
  parse error, and the captured output is discarded. Only the default spawn mode is usable
  in an expression position.
- `to_str` on an array produces the inspect form `[1, 2, 3]`, not `1,2,3`.
- `installer.iss` uses `IsTaskSelected`, which Inno Setup 6.7 renamed to
  `WizardIsTaskSelected`. It still compiles, with a deprecation hint.

## VS Code extension

Source lives in `vscode-extension/`. Manual install:

```bash
code --install-extension vscode-extension/kex-lang-1.0.0.vsix --force
```

It contributes a `kex` language (`source.kx`) with `//` and `/* */` comment
configuration, aliases `Kex` / `kx`, the `.kx` extension, and highlighting for template
strings, interpolation specs, logical assignment and the expanded builtin library.

The bundled `.vscode/tasks.json` adds a **KEXDRUN: Execute File** build task bound to
Ctrl+Shift+B, which runs the active file through the engine.
